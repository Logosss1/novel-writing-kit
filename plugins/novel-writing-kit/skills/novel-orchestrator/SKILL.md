# 小说任务路由器

## 定位

这是复杂任务的统一入口，不是“再写一遍正文”的 skill。核心 skill 可以独立使用；只有任务跨越多个阶段时才启用本路由器。

## 路由协议

1. 识别用户的主要动词和交付物：建立、规划、写作、检查、润色、核验、整理/压缩。
2. 判断任务是单阶段还是多阶段。单阶段只调用一个核心 skill；多阶段按最短可行链路执行。
3. 读取 `docs/routing.md`（若项目已复制该文件）或使用下方默认路由表。
4. 每个阶段只加载对应 skill 和它声明的输入文件，不预加载全部 skill。
5. 阶段完成后检查其“推荐下一步”和实际输出；只有满足条件才进入下一阶段。
6. 遇到冲突、缺失信息或需要用户选择时暂停并报告，不用猜测强行推进。

## 默认路由表

| 用户任务 | 调用顺序 |
| --- | --- |
| 新建小说项目 | `novel-architect` -> `novel-outline` |
| 重做世界观/人物设定 | `novel-architect` -> `novel-continuity` |
| 规划章节或分卷 | `novel-outline` -> `novel-memory`（若改变状态） |
| 续写或改写章节 | `novel-memory` -> `novel-draft` -> `novel-prose-edit` -> `novel-continuity` -> `novel-memory` |
| 续写中涉及现实知识 | 在 `novel-draft` 与 `novel-prose-edit` 之间插入 `novel-research` |
| 只润色一段文字 | `novel-prose-edit` |
| 只检查设定和逻辑 | `novel-continuity` |
| 只查资料 | `novel-research` |
| 整理或压缩上下文 | `novel-memory` |

## 交接格式

每个阶段结束时，用简短结构交接：

```text
完成：本阶段实际完成的工作
依据：读取或修改的文件
变更：人物 / 时间线 / 资源 / 伏笔 / 文本的变化
阻塞：仍需用户决定或核验的事项
下一步：skill 名称，或“结束”
```

不要把交接内容伪装成正文，也不要输出内部思维链。

## 报告策略

- 单阶段任务：只返回该 skill 的结果。
- 多阶段任务：阶段之间静默交接，只报告阻塞问题和最终结果。
- 章节完成：简要说明正文、审校和状态更新是否完成。
- 压缩或发现冲突：说明范围、影响和需要用户决定的事项。

## 显式调用优先

用户明确指定 `$novel-architect`、`$novel-outline` 等 skill 时，尊重该选择，不擅自扩展成完整流水线；只有用户同时要求“写完并检查”等多阶段结果时才补充后续步骤。

# 小说记忆与上下文管理

## 触发条件

- 新章节、设定、大纲或审查结果改变了项目状态。
- 用户要求整理进度、恢复上下文、压缩旧章节或跨会话继续写作。
- 当前上下文变长、重复内容增多或读取历史开始影响任务效率。

## 不适用场景

- 只做一次性润色、问答或资料查询，且没有改变项目状态时不必调用。
- 不用记忆摘要替代当前正文核验。
- 不因“可能有用”而创建大量空白账本。

## 输入文件

读取项目已有的状态卡、`progress.md`、`memory_index.md`、`hook_ledger.md`、`timeline.md`、章节摘要和最近相关章节。优先使用项目已有命名，不强制改名。

## 核心原则

- 把当前对话视为易失上下文，把项目文件视为持久记忆。
- 优先保存难以从正文快速重建的事实：人物状态、关系变化、时间线、规则、资源、伏笔和已确认决策。
- 最新正文和用户明确修改高于旧摘要、旧设定和推测。
- 压缩是信息重组，不是删除原文。除非用户明确要求，保留原章节和原始设定文件。

## 项目记忆文件

根据项目现有结构复用文件；缺失且任务确实需要时再创建：

- `chapter_state.md` 或状态卡：当前章节、时间、地点、在场人物、目标、资源、伤势、已知真相和未决问题。
- `progress.md`：最近完成内容、下一步、验证结果和阻塞项。
- `hook_ledger.md`：伏笔 ID、起始章节、类型、当前状态、最近推进、回收窗口和备注。
- `timeline.md`：故事内日期、事件顺序、地点和时间跨度。
- `memory_index.md`：记忆文件索引，每项只保留短标题、路径和用途。

如果项目已有等价文件，先读取并更新，不创建重复账本。

## 读取策略

1. 先读状态卡、进度、记忆索引和目标章节的直接相关文件。
2. 默认增量读取最近相关章节；只有全书复盘、长线伏笔或跨卷冲突才扩大范围。
3. 发现摘要与正文冲突时，回到原文核对并修正摘要，不让摘要覆盖事实。
4. 对旧章节只保留能支持当前决策的事实，避免机械加载全部历史。

## 何时压缩

在以下情况评估压缩：上下文接近平台容量、章节或资料持续累积、跨会话恢复变慢、或用户准备切换大型任务。没有可靠 token 计数时，根据文本规模、最近读取范围和重复内容做保守判断，不伪造精确数字。

压缩前说明范围和预计保留内容；如果用户正在进行紧接的创作，先保留当前场景和直接相关章节。

## 压缩方法

1. 保留完整的设定、角色规则、当前状态和最近仍在连续推进的章节。
2. 将较早章节转换为结构化摘要，每章至少记录：核心事件、人物状态变化、关键因果、伏笔、资源/数值变化和章末钩子。
3. 合并重复记忆，区分长期有效偏好、故事规则和已经结束的阶段性事实。
4. 把“下周、明天、过几天”等相对时间改写为故事内或现实中的明确日期；无法确定时标注未知，不猜测。
5. 更新 `memory_index.md`，移除已废弃或容易从正文重新获得的条目。
6. 压缩后重新读取摘要、状态卡和最近章节，确认主线、人物动机和伏笔没有断裂。

## 输出

报告压缩范围、保留范围、更新的文件、发现的冲突和剩余风险。日常续写只做静默维护；只有发生压缩、冲突或需要用户决策时才展开说明。

## 推荐下一步

- 状态可直接支持写作：交给 `novel-draft` 或 `novel-outline`。
- 发现设定冲突：交给 `novel-continuity`。
- 仅完成压缩或索引维护：任务到此结束。
